# 1.0.0 回归检查与动画修正

检查日期：2026-10-09。基线：`1b6b2d0`。范围从 `529d69d` 的 1.0.0 手动照片索引开始，覆盖扫描、动态筛选、分析图表、拍摄使用量榜以及已有应用回归。版本仍为 1.0.0。

## 修正

| 问题 | 修正与验证 |
|---|---|
| 新增空元数据列或切换未选列字段，不触发 facets 请求 | 列布局纳入 effect 依赖；组件测试验证新增与改字段均请求新分面 |
| 星期在 SQLite 中为整数，列筛选却生成字符串 | 字段注册为 number；前端生成 `[3]`，后端验证星期过滤与自排除分面 |
| 从预设恢复的多选 IN 条件无法正确编辑 | 补齐 IN/NOT IN 控件，允许逐字输入逗号列表；未完成输入保留草稿，不自动补 0 |
| 空条件组切到 NOT 或删去唯一子项导致非法 AST；UI 可创建超出后端深度的规则 | NOT 自动生成一条条件，删除时退回 AND，限制可创建层级 |
| 不合法 AST 子节点或范围值可能引起 500 | 在服务层验证节点、数字列表、between 两端；API 测试确认返回 422 |
| 解析失败的照片在指纹不变时永远被跳过 | 只有 parse_status=ok 的未变化文件跳过；失败照片下一次手动增量扫描重试 |
| 多来源扫描的 removed 仅显示最后一个来源 | 累计来源删除计数；两来源回归确认删除计数为 2 |
| 长解析批次等待期间进度不刷新，结束后可能遗留活跃线程值 | wait 每 250ms 返回以检查取消/持久化进度，失败/取消终态清零线程。已运行的 ExifTool 批次仍须结束，不宣称即时终止进程 |
| 扫描轮询重叠，卸载后响应可能更新状态，取消错误未反馈 | 完成一次轮询后再安排下一次，清理时失效；取消请求显示错误与等待说明 |
| 图表刷新卸载、页面塌缩、动画反复从零重播 | 保留现有图表 DOM，显示更新状态并淡化旧快照，加载期间忽略旧图表筛选 |
| Recharts 的 JavaScript 动画不受 CSS 减少动态效果规则控制 | 使用 AppSettingsProvider 的 reduceMotion，关闭 Bar/Pie/Area 动画 |
| 使用量榜加载中闪现空库，切到镜头时旧机身卡片可能跳错筛选 | 保留榜单并显示 busy 状态；旧链接暂不可用，目的地由已加载数据的 kind 决定 |

## 动画与交互参数

- 图表面板/元数据视图渐入：260ms，向上 8px；图表按 0/35/70/105ms 错开，延迟上限 105ms。
- Bar、Pie、Area 图形：420ms、ease-out、无额外起始等待。
- 进度、元数据覆盖率和使用量占比：使用 scaleX，450ms 过渡，避免反复改变布局宽度。
- 首次图表加载：四张骨架；刷新：保留旧图表、160ms 淡化。分类切换支持左右方向键和 Home/End，tab/panel 关联明确。
- 扫描枚举：不确定进度条仅在 queued/running 状态运行；失败/取消后静止，并明确文件总量未确定。
- 新增动画响应系统/应用的减少动态效果偏好；缩短或禁用视觉动画不会延迟数据查询。

## 验证边界

本环境没有真实 RAW 或 NAS 样本，模拟压力测试不能代表真实 RAW 解析速度。Docker 镜像构建与只读挂载未实测。云浏览器访问本地 Vite 地址返回 ERR_CONNECTION_REFUSED，因此没有完成截图、移动端/主题视觉验收或实际帧率测量。

构建仍提示主 JS 包约 794kB（gzip 约 229kB），应在后续性能工作中评估路由懒加载；这不是本次测试失败。已有 React Router future flag、SettingsPage 异步 act 和 Python 依赖弃用提示仍存在；本次新增图表测试没有零尺寸告警。
