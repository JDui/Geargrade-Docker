# 拍摄数据工作区的信息架构（1.0.0）

## 目标

筛选操作不应与数据可视化、元数据逐文件查看混为同一层级。自本次调整起，\`/photo-data\` 页面分为「页面级扫描与索引状态」「跨主视图的筛选工具」「两个主工作区」三层。

| 层级 | 功能 | 使用方式 |
|---|---|---|
| 页面操作区 | 只读来源、增量/深度扫描、并行进度、取消与最近扫描 | 保留在拍摄数据页顶部 |
| 全局工具栏 | 当前数据范围与筛选摘要、工作区切换、打开全局筛选 | 在图表和明细工作区之间共用 |
| 全局筛选抽屉 | Lightroom 元数据列（同列 OR、跨列 AND）、嵌套 AND/OR/NOT、高级条件、预设保存/加载/删除、导出 | 点击「全局筛选」以侧抽屉打开，应用后影响两个主工作区 |
| 主工作区：统计分析 | 总览、器材与组合、曝光与焦距、拍摄时间、文件与质量 | 页面默认主工作区；图表内部分类保持原来的独立导航 |
| 主工作区：照片明细 | 索引文件分页表、文件名/路径查找、每页条数、单文件元数据详情、导出结果 | URL \`/photo-data?view=files\`；不会同时渲染整套图表 |

## 筛选语义

- 选择图表的柱条、日历日期、热力单元格后，会把条件应用至同一个全局筛选 AST，顶部工具栏实时显示条件摘要。
- 全局筛选状态由拍摄数据页持有，切换两个主工作区不会清除筛选条件。来自摄影使用量排行榜的 \`camera\`/\`lens\` URL 参数仍在初始化时生效。
- 文件明细中的文字检索使用额外条件 \`files.relpath contains\`，**仅作用于明细分页、明细数量与该工作区的导出**，不会改变统计分析中的聚合口径或全局筛选预设。
- 仅在全局筛选抽屉打开并切换到「元数据列」时请求字段 Facet；仅在「照片明细」主工作区打开时请求文件行。统计分析工作区只获取聚合数据。过滤器及明细表不再常驻页面。
- 主工作区通过 URL 的 \`view=files\` 标识；缺省为统计分析。保留已有的摄影使用量榜链接和 URL 参数。
- 高级规则支持跨列条件组合。元数据列选项与图表点击筛选统一编译到后端版本化 \`photo-filter.v1\`，全部 SQL 值经绑定参数传入。
- 当全局筛选条件改变时，明细分页归零；切换每页条数或更改搜索文本也归零。搜索输入做 240ms 防抖。
- 抽屉支持 Escape 关闭、Tab 焦点循环和关闭后返回筛选按钮；文件详情支持 Escape 关闭和焦点归位；小屏抽屉铺满屏幕。

## 数据与隐私

- 文件明细搜索操作 \`files.relpath\` 在 SQLite 里查询，不访问 DCIM 真实目录。
- 点击行仅查看 \`/query\` 响应返回的有限元数据字段，包含相对路径、机身镜头、光圈快门、焦距与分辨率，不包含图片预览或 GPS。
- 文件数量与逻辑拍摄数始终分别统计；RAW+JPEG 配对没有改变。
- 文档中的工作区布局仅描述已经提交的前后端功能，未实现的图像像素分析和地图分析不属于此范围。
